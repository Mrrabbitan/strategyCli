# 三步筹码选股法

版本 1.0.0。自然语言或 `$a-share-three-step` 均可调用。只做最近完整交易日的收盘观察，全部满足才入选；不是三套任选条件，也不是收益概率模型。

## 执行

1. 读取 [规则](references/rules.md) 与 [数据契约](references/data.md)。以上海时间解析分析时点，盘中取最近完整收盘日；指定历史日期须用相应截面证据，不用今天证券状态替代历史。
2. 先核全主板目录、证券状态、成交股数与当日有效流通A股数，冻结全池换手名次；再算三日价格；只为尚可进入下一步的项目补筹码和历史封板。
3. 只执行本技能 `scripts/engine.py` 的确定性规则。`scripts/run.py --input <证据.json> --as-of <ISO时点>` 接收已核验文件；`scripts/validate_input.py <证据.json>` 运行契约与结果校验。运行固定内核需要 Node，可设置 `NODE_BINARY`；不可用则待验证，不替换算法。
4. 在投资工作台项目内使用 `python3 refresh_research.py --module three-step`；历史/指定日期使用 `--as-of` 和私有 `--input`。页面构建只读报告，不联网选股。`all` 维持原四模块，不能借此次新增改变定时任务。
5. 首先报告信号日、执行时间、规则与模型版本、覆盖和阻断，再列每步进入/通过/淘汰/待验证/未进入数量。展示全部最终候选、三日累计收益、同日获利比例、全池换手名次、60日封板日期、风险与来源；按换手名次排序，不凑十只。
6. 研究变化使用现有私有快照、锁和原子发布更新独立“三步选股”页；保留最后完整成功结果和最新失败/不完整尝试。数据与页面仅留本地；Git仅提交通用代码、规则和虚构样例。

## 不可绕过的边界

- 三个获利比例门槛严格大于60%/70%/80%；使用同一信号日，最终实质门槛>80%。筹码是模型估算，不是同花顺值、真实账户盈利占比或主力成本。
- 固定 AKShare 1.18.60 内核，210根完整前复权日K、原生换手；不直接调用默认联网函数，不混入今天未完成K线。读取 `vendor/model.json` 验证内核、版本和许可证；不得把注释中的120日参数启用。保留输入与来源指纹。
- 确认全池排名需要完整资格、状态与换手覆盖；未知不得填0或通过。涨停使用当日未复权收盘与有效涨停价，不能用涨幅≥9.9%近似。
- 接口重试有上限，缓存必须同源、同信号日、同复权截面并通过指纹；仍缺数据展示实际进度，不编造候选或成功空池。
- 不复用龙空龙、尾盘或潜伏策略的量能、评分、买卖门槛、仓位与退出规则。无自动买卖、提醒或新定时任务。T+1和涨跌停可能阻碍交易；规则测试不证明赚钱。
